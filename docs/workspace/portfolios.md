A **portfolio** is a named group of projects that you read together. It answers "how are all of these doing?"
without opening each board. A portfolio changes nothing about the projects in it: it is only a view.

It is different from a goal. A goal is an outcome with a status and a progress of its own. A portfolio has no status
of its own; it reports on its projects. See [Goals and sub-goals](/help/workspace/goals) for the other one.

## Who sees portfolios

Portfolios belong to the workspace you are in. In a team, every member sees the team's portfolios and any member can
change or delete them: the server does not check a role here. In your Personal Workspace only you see yours.

## Make one

1. Open **Portfolios** in the sidebar.
2. Type a name in the box, such as "Marketing". **Add portfolio** stays off until there is text.
3. Press **Add portfolio**. The new portfolio opens its settings so you can add projects.

While you have no portfolio yet, the page shows a line saying what a portfolio is. A new portfolio with no projects
says **No projects yet. Open the settings to add some.**

## Add and remove projects

1. On the portfolio, click the settings button (**Edit portfolio**).
2. Under the name, tick the projects that belong in it. Untick one to take it out.

The list only offers projects you work on as staff in the current workspace. Click the button again (it now shows an
arrow up) to close the settings.

You can also rename the portfolio here: edit **Name**, and it saves when you leave the field.

## Reading a portfolio

The top row of a portfolio shows:

- its name;
- three small counts, each next to a coloured dot, for **on track**, **at risk** and **off track**: how many of its
  projects have each health. The dots carry no words; the colours match the project's health status;
- a bar and a percentage: the average of how much of each project is done.

Below it, a table has one row per project, ordered by name:

| Column | What it says |
|---|---|
| **Project** | The project's name. Click it to open the board. |
| **Status** | The project's health, or **Not set** when nobody has set one. |
| **Done** | A bar, with how many tasks are done out of how many there are, for example 7/10. |
| **Latest update** | The words of the project's newest status update, or a dash when there is none. |

A project counts a task as done when the task is marked done or sits in a finishing column. Only top-level tasks
count; subtasks are not included. A project without tasks shows 0%.

The status and the latest update come from the board itself: whoever works on the project sets its health and posts
status updates there. If a portfolio looks stale, the fix is an update on the project, not in the portfolio.

A project with no health set is not counted in any of the three health numbers, so those can add up to fewer than the
number of projects in the portfolio.

If a portfolio has no projects, it says **No projects yet. Open the settings to add some.**

## Delete a portfolio

1. Open the portfolio's settings with **Edit portfolio**.
2. Click **Delete portfolio**, then **Delete** in **Delete this portfolio?**.

This cannot be undone, but only the grouping is lost: the projects in it are untouched.

If a change is refused you get a message such as **Could not save the portfolio**. The page also updates by itself
when someone else changes a portfolio or the work behind it.
