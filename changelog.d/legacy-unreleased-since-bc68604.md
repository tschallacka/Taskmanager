- **A crew backs up and restores its own board.** A crew key, refused on every board until now, may import a backup into the crew's own board: its shadow board, or the board the crew was made on, both in the crew's own team (`isOwnCrewBoard` in `server/utils/crewBoardAccess.ts`). Its backup of that board is the whole board, as an admin's is (addresses still follow each person's visibility setting); on any other board a crew key still gets the customer view and is refused the import, and it still cannot create a board by import. So a crew can move its work from one instance to another and put it back. `server/utils/boardImport.ts`, `server/utils/boardImportRequest.ts`, `server/api/projects/[id]/backup.get.ts`, `tests/board-import.test.ts`, `docs/team/board-import.md`, `docs/team/board-backup.md`.

- **A connection token with per-board permissions can use the backup and the import over HTTP.** `GET /api/projects/:id/backup` and `POST /api/projects/:id/import` answered 404 "Project not found" for a token made with "Connect your Claude to this board" (a permission chosen per board), because such a token reaches a board only for the permission of the call being made and these two routes never said which one that was. The backup is now a read call and the import a write call (`forCall` in `server/utils/api-keys.ts`), as the MCP tools already were. Ordinary keys are unchanged. `server/utils/api-keys.ts`, `server/api/projects/[id]/backup.get.ts`, `server/utils/boardImportRequest.ts`, `tests/board-key-scope.test.ts`.

- **Board import: `POST /api/projects/:id/import` and `POST /api/projects/import`.** An admin (the instance admin, or an owner or admin of the board's team) loads a board backup into an existing board, or into a new one, with every original timestamp kept. `?dryRun=1` checks the file and writes nothing; `columnMap` and `authorMap` map the backup's columns and people onto this board and these accounts, and people who cannot be mapped are kept as a name next to the update (`author_label`). Importing the same backup again skips what is there (new table `board_imports`). The import sends no notification, agent event, rule run or GitHub call. An API key needs the ordinary write permission for the board and an admin owner; a crew key is always refused. The backup route now also accepts an API key past the sign-in middleware. Board settings gets an Import a backup button with the dry-run report first. Additive schema: `task_comments.author_label`, `task_activity.author_label`, `board_imports`. `server/utils/boardImport.ts`, `boardImportPlan.ts`, `boardImportRequest.ts`, `server/api/projects/[id]/import.post.ts`, `server/api/projects/import.post.ts`, `server/middleware/requireAuth.ts`, `docs/team/board-import.md`.

- **Board backup: `GET /api/projects/:id/backup`.** Anyone who can read a board can download one JSON file (format `taskmanager-board-backup`, version 1) with the columns, cards, subtasks, labels, custom fields, updates, messages and every timestamp as stored, filtered to what that caller may see: a customer contact or guest gets the customer view, an unauthorised caller a 404. Privacy-sensitive material (email addresses, display names, time entries, key and agent identities, rules) is in an admin's backup only (the instance admin, or an owner or admin of the board's team); everyone else's file has people as a tag and an id. Secrets, keys, tokens and sessions are in no backup. The file is streamed, carries an `ETag` (304 on an unchanged board), and a caller may download six per hour per board. Board settings gets a Download backup button. `shared/backup/schema.ts`, `server/utils/boardBackup.ts`, `server/utils/boardAdmin.ts`, `server/api/projects/[id]/backup.get.ts`, `docs/team/board-backup.md`.

- **A revoked management token answers its sentence over the public URL.** A remote call with a revoked management token now gets 401 with the `token_revoked` sentence, like an expired or regenerated one, instead of the plain 404. Revoking records the secret as `revoked_management` in `api_key_secrets.state` (a text column, so no schema change), which keeps the kind after the key row is deleted. Revoked access tokens and unknown keys still get the plain 404. `server/utils/crewGate.ts`, `server/utils/connectTokens.ts`, `server/utils/api-keys.ts`, `server/db/schema.ts`, `tests/crew-gate-management.test.ts`, `docs/admin/crews-on-your-instance.md`.
